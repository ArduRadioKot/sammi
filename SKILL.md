# Premium Web Design System Skill

## 0. Миссия

Создавай сайты, которые ощущаются **современными, уверенными, премиальными и технологичными**, но не выглядят как шаблонный «AI landing page».

Визуальный язык строится на сочетании:

- выразительности **Grainient**;
- арт-дирекшна и ритма **Mutabor.AI**;
- кинематографичной технологичности **Aries**;
- интеллектуальной строгости **Feelistic**;
- cyber/enterprise-ясности **Cystel**;
- дружелюбной продуктовой простоты **Lovable**;
- институционального доверия **Harvey**;
- системности и accessibility **Material Design 3**;
- глубины, стекла и motion-принципов **iOS 27 Design System**.

**Главное правило:** не копируй страницы, секции, логотипы, иллюстрации, фирменные шрифты или узнаваемую композицию референса 1:1. Бери принципы и собирай новую систему под продукт.

# 1. Основная дизайн-философия

## 1.1. Один сильный визуальный жест на экран

На одном viewport должен доминировать **один** художественный приём:

- градиент;
- жидкое стекло;
- типографика;
- фотография;
- product UI;
- data visualization;
- абстрактный motion-object.

Не смешивай одновременно mesh gradient + glow + glass + particles + 3D sphere + grid + noise + neon borders.

**Формула:**

> 1 spectacle + 1 message + 1 action + quiet supporting UI.

## 1.2. Контраст «эмоция ↔ система»

Лучшие страницы из референсов работают за счёт двух слоёв:

1. **Эмоциональный слой** — hero, крупная типографика, изображение, gradient, liquid surface.
2. **Системный слой** — строгая сетка, спокойные карточки, короткий текст, понятные CTA.

Если весь сайт эмоциональный — он становится шумным.
Если весь сайт системный — он становится безликим.

## 1.3. Цвет должен иметь роль

Не используй «AI-purple» автоматически.

Каждый цвет должен отвечать за одну из функций:

- brand atmosphere;
- primary action;
- status;
- depth;
- emphasis;
- data category.

Не используй один и тот же акцент одновременно как фон, кнопку, ссылку, границу и декоративный glow.

## 1.4. Typography first

Если страницу можно сделать выразительной только текстом и сеткой — сначала сделай именно так.
Декор добавляется после того, как работает hierarchy.

## 2.8. Material Design 3 — semantic system

Источник: https://m3.material.io

### Что брать

- semantic color roles вместо raw hex everywhere;
- component states как часть дизайна, а не afterthought;
- consistent elevation / surface hierarchy;
- responsive layout logic;
- clear shape scale;
- predictable component anatomy;
- accessibility как foundation;
- design tokens как single source of truth.

### Основной принцип

Пиши не `color: #6750A4`, а `color: var(--color-primary)`.
Пиши не `background: #fff`, а `background: var(--surface-1)`.

Компонент должен знать **роль**, а не конкретный цвет.

## 2.9. iOS 27 Design System — liquid glass + tactile motion

Источник: https://github.com/seunghan91/ios27-design-system

### Что брать

- 8pt-oriented spacing;
- light/dark parity;
- glass как материал с контролируемой прозрачностью;
- darkened edge + bright specular edge;
- soft diffusion поверх busy background;
- spring-like motion;
- minimum 44×44 interactive target;
- layered material hierarchy;
- explicit reduced motion / reduced transparency behavior.

### Главное правило Liquid Glass

Стекло **не является background theme**. Оно применяется к небольшому числу плавающих или навигационных поверхностей:

- top bar;
- floating control;
- search capsule;
- modal/tool palette;
- contextual controls.

Не делать весь сайт из blur-card.

# 4. Color tokens

Используй палитру как **набор ролей**, а не одновременно.

```css
:root {
  /* neutrals */
  --ds-black: #080908;
  --ds-charcoal: #171817;
  --ds-paper: #f7f4ed;
  --ds-white: #fcfbf8;

  /* optional accents */
  --ds-blue: #6aa7ff;
  --ds-violet: #8c7cff;
  --ds-pink: #ff6bd6;
  --ds-orange: #ff7a3d;
  --ds-teal: #63d6c5;
  --ds-gold: #d7aa62;
  --ds-cyan: #44c7f4;

  /* semantics */
  --color-primary: var(--ds-blue);
  --color-on-primary: #08101e;
  --color-positive: #3ac985;
  --color-warning: #e7b655;
  --color-negative: #ff665f;
  --focus-ring: #88b8ff;
}
```

## 4.1. Accent discipline

На одну страницу выбери:

- **1 primary accent**;
- максимум **1 secondary atmospheric accent**;
- neutrals.

Исключение: prismatic hero, где несколько цветов составляют **один** gradient-object.

### Примеры

- Developer tool: blue + prismatic hero.
- Enterprise AI: teal + neutral.
- Legal AI: no bright accent, mostly warm monochrome.
- Regulated finance: gold + neutral.
- Cyber: cyan + navy-black.

# 6. Typography system

Не копируй закрытые фирменные шрифты референсов.

## 6.1. Recommended stack

```css
--font-sans: "Manrope", "Inter", ui-sans-serif, system-ui, sans-serif;
--font-editorial: "Newsreader", "Source Serif 4", Georgia, serif;
--font-mono: "IBM Plex Mono", "SFMono-Regular", Consolas, monospace;
```

## 6.2. Type scale

```css
--text-xs: clamp(.72rem, .70rem + .08vw, .78rem);
--text-sm: clamp(.82rem, .79rem + .12vw, .92rem);
--text-md: clamp(1rem, .96rem + .16vw, 1.1rem);
--text-lg: clamp(1.18rem, 1.08rem + .35vw, 1.45rem);
--text-xl: clamp(1.5rem, 1.28rem + .7vw, 2rem);
--text-2xl: clamp(2rem, 1.55rem + 1.6vw, 3.25rem);
--text-3xl: clamp(3rem, 2.1rem + 3vw, 5.75rem);
--text-hero: clamp(3.5rem, 2.1rem + 5vw, 7.5rem);
```

## 6.3. Display rules

Hero heading:

```css
font-size: var(--text-hero);
line-height: .94;
letter-spacing: -0.045em;
font-weight: 520;
max-width: 11ch;
```

Section heading:

```css
font-size: var(--text-2xl);
line-height: 1.02;
letter-spacing: -0.03em;
font-weight: 520;
```

Body:

```css
font-size: var(--text-md);
line-height: 1.55;
max-width: 62ch;
```

## 6.4. Serif usage

Используй serif **только** если продукту нужны:

- authority;
- editorial tone;
- institutional trust;
- legal / finance / professional services character.

Не смешивай serif display с futuristic techno-font.

# 9. Surface & depth

## 9.1. Border-first depth

По умолчанию предпочитай border перед shadow.

```css
.card {
  border: 1px solid var(--line);
  background: var(--surface-0);
}
```

## 9.2. Soft shadow

```css
box-shadow:
  0 1px 0 rgba(255,255,255,.04) inset,
  0 20px 60px rgba(0,0,0,.12);
```

Не использовать material-like огромную тень под каждой карточкой.

# 10. Liquid Glass recipe

Использовать только там, где фон под элементом действительно виден.

```css
.glass {
  background: rgba(255,255,255,.075);
  backdrop-filter: blur(24px) saturate(140%);
  -webkit-backdrop-filter: blur(24px) saturate(140%);
  border: 1px solid rgba(255,255,255,.14);
  box-shadow:
    inset 0 1px 0 rgba(255,255,255,.20),
    inset 0 -1px 0 rgba(0,0,0,.26),
    0 16px 48px rgba(0,0,0,.18);
}
```

Light version:

```css
.glass-light {
  background: rgba(252,251,248,.62);
  backdrop-filter: blur(22px) saturate(125%);
  border: 1px solid rgba(27,27,26,.09);
  box-shadow:
    inset 0 1px 0 rgba(255,255,255,.82),
    0 16px 45px rgba(27,27,26,.08);
}
```

## Reduced transparency

```css
@media (prefers-reduced-transparency: reduce) {
  .glass,
  .glass-light {
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
    background: var(--surface-0);
  }
}
```

Если `prefers-reduced-transparency` не поддерживается целевой средой, предложи обычный theme setting / class fallback.

# 11. Components

## 11.1. Navigation

Desktop height: 64–76px.

Anatomy:

- logo left;
- 3–5 primary items;
- optional compact mega-menu;
- utility action;
- one primary CTA.

Hero variant:

- transparent or subtle glass;
- no heavy border-bottom;
- background becomes opaque/glass after scroll.

Mobile:

- logo;
- one CTA only if essential;
- menu trigger at least 44×44px;
- menu becomes full-height or large sheet, not tiny dropdown.

---

## 11.2. Buttons

Minimum target: **44×44px**.

### Primary

```css
.btn-primary {
  min-height: 44px;
  padding: 0 20px;
  border-radius: 8px;
  background: var(--ink);
  color: var(--bg);
  border: 1px solid transparent;
}
```

### Secondary

```css
.btn-secondary {
  min-height: 44px;
  padding: 0 20px;
  border-radius: 8px;
  background: transparent;
  color: var(--ink);
  border: 1px solid var(--line);
}
```

### Glass control

Use only for floating / immersive context.

### Button copy

Good:

- Start building
- Explore the platform
- Request a demo
- See how it works
- View case study

Bad:

- Learn More on every section
- Click Here
- Get Started Now!!!

---

## 11.3. Hero

Hero is a scene, not a stack of random content.

### Anatomy

1. optional eyebrow;
2. headline;
3. one supporting paragraph;
4. 1–2 CTA;
5. one visual centerpiece;
6. optional trust cue.

### Recommended dimensions

Desktop:

- min-height: 78–100svh;
- headline max-width: 8–13ch;
- support max-width: 44–60ch.

Mobile:

- min-height: auto;
- visual below copy;
- never force 100vh if keyboard/browser chrome makes it awkward.

### Hero visual options

Choose one:

- gradient field;
- liquid abstract image;
- product UI stage;
- editorial photo;
- interactive canvas;
- data object.

---

## 11.4. Product stage

Для Lovable / Harvey-like продукта:

- одна большая UI frame;
- inset shadow, subtle border;
- viewport corners 10–18px;
- real interface hierarchy;
- no fake illegible screenshot wall.

Вокруг UI допускаются 2–4 floating annotations максимум.

---

## 11.5. Feature cards

Cards must not all be identical.

Use hierarchy:

- 1 primary feature = 2× area;
- 2–4 secondary features;
- simple text rows for tertiary details.

Good card anatomy:

- label;
- short title;
- 1–3 line description;
- meaningful visual / metric;
- optional detail link.

Не использовать icon-circle + title + paragraph × 12.

---

## 11.6. Trust strip

Лучше:

- monochrome logos;
- simple proof line;
- 5–8 logos per row;
- low visual contrast.

Не делать trust logos ярче hero.

---

## 11.7. Stats

Use large type, tiny label.

```text
25+
Hours saved / month
```

Numbers should be evidence, not decoration.

## 11.8. Testimonials

Harvey-like approach:

- real name;
- real title;
- company;
- editorial portrait when available;
- quote no longer than 2–4 short sentences.

Avoid carousel with 12 anonymous avatars.

## 11.9. Footer

Footer can be a final brand moment.

Structure:

- strong final CTA;
- horizontal divider;
- 3–6 navigation groups;
- legal / social;
- oversized wordmark or subtle visual anchor.

Dark product can keep dark footer.
Light product may switch to dark footer for closure.

# 12. Motion system

Motion should communicate physics and hierarchy.

## 12.1. Timing

```css
--motion-fast: 160ms;
--motion-base: 240ms;
--motion-slow: 480ms;
--motion-scene: 720ms;
--ease-standard: cubic-bezier(.2,.8,.2,1);
--ease-emphasized: cubic-bezier(.16,1,.3,1);
```

## 12.2. Hover

Buttons:

- translateY: -1px;
- scale max 1.01;
- opacity / fill shift;
- 160–220ms.

Cards:

- translateY max -4px;
- no dramatic 3D tilt by default.

## 12.3. Scroll reveal

Default:

```css
opacity: 0 → 1
transform: translateY(16px) → translateY(0)
duration: 480–650ms
```

Stagger: 40–70ms.

Never animate every word independently unless hero concept specifically requires it.

## 12.4. Gradient motion

- 12–30 seconds;
- low amplitude;
- seamless loop;
- no fast color cycling.

## 12.5. Spring feel

Use spring-like easing for:

- sheets;
- floating controls;
- nav transitions;
- selected tab / segmented control;
- expandable cards.

## 12.6. Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: .01ms !important;
  }
}
```

---

# 13. Interaction states

Каждый interactive component обязан иметь:

- default;
- hover;
- active / pressed;
- focus-visible;
- disabled;
- loading, если действие async;
- error, если input/action может завершиться ошибкой.

Focus ring must be visible.

```css
:focus-visible {
  outline: 2px solid var(--focus-ring);
  outline-offset: 3px;
}
```

Не удаляй outline без равноценной замены.

---

# 14. Accessibility

Минимум:

- body text contrast ≥ 4.5:1;
- large text contrast ≥ 3:1;
- interactive target ≥ 44×44px;
- keyboard navigation;
- visible focus;
- semantic headings;
- `alt` для meaningful images;
- `aria-label` только когда native label недостаточен;
- reduced motion;
- fallback для glass/transparency;
- content not encoded only by color.

## Busy background rule

Если текст находится на gradient / photo / liquid image:

- используйте local scrim;
- или blur field;
- или move text into solid surface.

Никогда не надеяться, что «сейчас вроде читается».

---

# 15. Responsive behavior

## Desktop → tablet

- 12 columns → 6;
- hero visual shrinks before headline shrinks aggressively;
- nav becomes condensed;
- multi-column cards reduce columns;
- decorative elements disappear first.

## Tablet → mobile

- 6 → 4 columns;
- text remains large enough to preserve character;
- 2-column cards → 1 column;
- horizontal feature rail may become swipeable;
- large product mockup may crop intentionally;
- sticky floating controls must avoid covering CTA/content.

## Mobile rule

Do not create a different aesthetic. Create the same system with fewer simultaneous elements.

---

# 16. Content design

## 16.1. Headline

Target: 3–10 words.

Prefer:

- a clear outcome;
- a point of view;
- a sharp contrast;
- a memorable claim.

Avoid generic:

- “Revolutionize Your Workflow with AI”;
- “Unlock the Power of Innovation”;
- “The Future Is Here”.

## 16.2. Supporting copy

1–3 sentences.
Explain:

- what the product is;
- who it is for;
- what changes after using it.

## 16.3. Section labels

Use small utility labels to create editorial rhythm:

```text
PLATFORM
AI EXPLORATION
SECURITY
01 / CONTEXT
WHY IT MATTERS
```

Do not put uppercase label above every single card.

---

# 17. Imagery

## 17.1. Preferred imagery

- real product interface;
- real people / documentary photography for trust;
- abstract material studies for frontier tech;
- visualized system behavior;
- real charts and data;
- high-quality custom illustrations.

## 17.2. Avoid

- generic robot head;
- humanoid hand touching hologram;
- hooded hacker;
- random 3D chrome blob with no brand relevance;
- meaningless neuron network;
- stock corporate handshake.

---

# 18. Icons

Use icons as utility, not decoration.

Rules:

- one icon family;
- 1.5–2px stroke for outline family;
- 16 / 20 / 24px base sizes;
- optical alignment;
- icon buttons ≥ 44×44px target;
- colored icons only when semantic or brand-relevant.

Do not place an icon in a colored circle for every feature by default.

---

# 19. Data visualization

For analytics / intelligence products:

- background neutral;
- one highlight series;
- secondary series muted;
- labels direct when possible;
- grid lines low contrast;
- tooltips compact;
- avoid neon rainbow charts.

Data should reinforce the brand without reducing interpretability.

---

# 20. Design tokens architecture

Follow:

```text
Primitive tokens
  ↓
Semantic tokens
  ↓
Component tokens
  ↓
Components
  ↓
Patterns / sections
  ↓
Pages
```

## Example

```css
:root {
  /* primitive */
  --neutral-950: #080908;
  --neutral-50: #fcfbf8;
  --blue-500: #6aa7ff;

  /* semantic */
  --background: var(--neutral-50);
  --foreground: #1b1b1a;
  --primary: var(--blue-500);
  --border-subtle: rgba(27,27,26,.12);

  /* component */
  --button-primary-bg: var(--foreground);
  --button-primary-fg: var(--background);
  --card-border: var(--border-subtle);
}
```

Do not put arbitrary color literals inside 40 separate components.

# 23. Anti-patterns

Never default to:

1. Purple gradient text on every heading.
2. 3-column feature grid repeated 4 times.
3. Every card with icon in colored circle.
4. Huge blur/glow behind every element.
5. Glassmorphism everywhere.
6. 32px radius on all containers.
7. Animated particle background behind body copy.
8. Fake dashboard with unreadable microtext.
9. 10 separate accent colors.
10. Generic stock AI imagery.
11. Scroll-jacking.
12. Cursor replacement unless concept absolutely requires it.
13. Autoplay sound.
14. Parallax on every image.
15. CTA repetition after every paragraph.
16. Gradients on all buttons.
17. Low-contrast gray-on-gray text.
18. Hidden focus styles.
19. Desktop-first layout that merely stacks on mobile.
20. Copying the exact composition of a reference.

# 24. Implementation protocol for AI coding agents

When asked to design or implement a page with this skill, follow this order.

## Step 1 — classify the product

Choose one:

- Creative AI
- Enterprise AI
- Regulated AI
- Cybersecurity
- Developer tool
- Editorial / professional services
- Hybrid

## Step 2 — choose one primary reference family

Example:

```text
Primary: Harvey
Secondary: Aries + iOS 27
```

Never blend all references equally.

## Step 3 — set tokens before components

Define:

- background;
- surfaces;
- text colors;
- primary accent;
- typography;
- spacing;
- radius;
- motion;
- glass behavior.

## Step 4 — design hierarchy in grayscale

Before gradients, verify:

- hero readable;
- CTA visible;
- sections distinct;
- scan path works;
- mobile order makes sense.

## Step 5 — add one brand spectacle

One of:

- gradient field;
- liquid visual;
- editorial photo;
- product stage;
- data scene.

## Step 6 — implement component states

Do not ship static-only controls.

## Step 7 — responsive pass

Test at minimum:

- 360px;
- 390px;
- 768px;
- 1024px;
- 1440px.

## Step 8 — accessibility pass

Check:

- contrast;
- focus;
- keyboard;
- touch target;
- reduced motion;
- reduced transparency;
- semantic markup.

## Step 9 — remove 20% of decoration

If the result feels impressive but slightly noisy, remove decoration before adding anything else.

# 25. Quality checklist

Before considering the site complete, verify:

- [ ] There is one clear visual concept.
- [ ] The page does not look like a generic AI SaaS template.
- [ ] Hero headline is understandable without supporting paragraph.
- [ ] There is only one primary CTA per main decision point.
- [ ] Accent color has a semantic role.
- [ ] Gradient is used intentionally.
- [ ] Glass appears only where translucency has a reason.
- [ ] Typography carries most of the hierarchy.
- [ ] Cards do not all have identical importance.
- [ ] There is enough negative space.
- [ ] Product screenshots are legible.
- [ ] Motion is slow enough to feel premium.
- [ ] Hover motion is subtle.
- [ ] Reduced motion is implemented.
- [ ] Focus-visible is implemented.
- [ ] Interactive targets are at least 44×44px.
- [ ] Mobile preserves the design concept.
- [ ] Body copy has comfortable contrast and line length.
- [ ] No decorative visual competes with CTA.
- [ ] No section exists only to “fill the landing page”.
- [ ] Visual references are synthesized, not copied.

---

# 26. Final decision rules

If unsure between two choices:

- choose **less color**;
- choose **larger typography**;
- choose **fewer cards**;
- choose **more whitespace**;
- choose **one stronger image** instead of many weak images;
- choose **clearer copy** over decorative copy;
- choose **border** over shadow;
- choose **semantic token** over hard-coded value;
- choose **subtle motion** over flashy motion;
- choose **real product evidence** over abstract AI decoration.

The intended result should feel like a product designed by a strong brand team and a strong product team together — not like a template with expensive effects layered on top.
